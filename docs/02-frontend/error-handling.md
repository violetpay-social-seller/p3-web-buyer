# Error Handling

## 사용자 표시

- 최초 로딩은 Skeleton, 작은 갱신은 기존 데이터와 진행 표시를 사용한다.
- Empty는 오류가 아니라 데이터가 없는 이유와 가능한 주요 행동을 표시한다.
- Error는 이해 가능한 메시지, 재시도, 안전한 이동 경로를 제공한다.
- 주문서·결제·주문 취소 실패 시 사용자가 입력한 값과 첨부 상태를 가능한 한 유지한다.

## API 에러

| 상태 | 처리 |
| --- | --- |
| 400 | 필드 오류를 입력에 연결하고 나머지는 Form Alert에 표시 |
| 401 | Auth Adapter 갱신을 한 번 시도하고 실패하면 Return URL과 함께 로그인 이동 |
| 403 | `/forbidden` 또는 화면 내부 권한 없음 |
| 404 | 목록으로 돌아갈 수 있는 Not Found |
| 409 | 최신 데이터 재조회 후 충돌 안내 |
| 422 | 도메인 Validation 오류를 입력 필드 또는 행동 영역에 표시 |
| 429 | 재시도 가능 시각 안내와 반복 요청 차단 |
| 500 이상 | 요청 ID가 있으면 함께 표시하고 재시도 제공 |

## 로깅

- 개발 환경에서는 알 수 없는 Enum, 무시된 동적 필드 설정, Point3 Origin 불일치를 경고한다.
- 운영 환경에서는 개인정보, 결제 식별값, 토큰을 로그에 남기지 않는다.
- 사용자에게 노출 가능한 오류에는 `requestId`만 함께 제공한다.
